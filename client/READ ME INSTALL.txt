MikroTik Tools for GLPI — Client setup

INSTALL
1. Download Winbox-GLPI-Setup.exe from the GLPI setup page and run it on the Windows computer used to access GLPI.
2. The installer registers the WinBox, PuTTY, and SSH diagnostic handlers for the current Windows user and removes the obsolete KiTTY handler.
3. It leaves compatible existing programs unchanged. It downloads only missing or incompatible clients from official HTTPS sources, verifies pinned SHA-256 hashes, and stores managed copies under %LOCALAPPDATA%\Winbox-GLPI\clients.
4. No administrator rights, PowerShell commands, or separate .reg file are required. Internet access to the relevant official download host is required only if a client must be added.
5. Run the installer again to repair protocol handlers or retry a failed download.

CONNECT WITH WINBOX
1. In GLPI, open a network equipment record and choose the Winbox tab.
2. Click Open in Winbox, then click Start Winbox on the handoff page within 90 seconds.
3. Confirm the browser prompt if it asks to open an external application.

CONNECT WITH PuTTY
1. In the device's Winbox tab, choose Open SSH in PuTTY.
2. Click the matching start button on the handoff page within 5 minutes. SSH handoff codes are single-use.
3. The selected client receives the configured host, SSH port, username, and saved password. Users do not enter credentials at launch.
4. PuTTY uses a short-lived password file. KiTTY integration was removed because its automatic password option exposes the saved password in the command line. The installer leaves separately installed KiTTY applications alone.
5. If RouterOS rejects authentication, verify the saved device credentials and RouterOS SSH policy. The handler cannot bypass an authentication rejection.

DIAGNOSTICS AND LOGS
- Setup and client launch log: %LOCALAPPDATA%\Winbox-GLPI\winbox-glpi-launch.log
- Temporary SSH diagnostic log: %LOCALAPPDATA%\Winbox-GLPI\winbox-glpi-ssh-test.log
- In GLPI, Test SSH login runs a single read-only identity check using Plink. It does not change router configuration.
- Send sanitized log events to the GLPI administrator. Do not share passwords, launch codes, router configuration, or customer data.

SECURITY
- Use HTTPS for GLPI when exchanging production credentials. The test GLPI server uses HTTP and is for test credentials only.
- The installer is unsigned. Download it only from a GLPI server you trust.
- Manual fallback files are available on the GLPI setup page, but they do not install SSH clients.
